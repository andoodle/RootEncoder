The decision Andy asked for

Nothing retired

›

Upstream's three areas of work this round — send-queue statistics, an encoder reset budget, camera white-balance controls — don't overlap any GPX patch. Every item is keep and re-apply. The three that looked like genuine retire candidates until the code was read:

R7 survives

Upstream's INSUFFICIENT verdict reads the send queue, which also grows on a congested-but-alive link. R7 detects a UDP blackhole and fails the connection. Different fault.

R12 survives

Upstream counts bytes queued on the send path. R12 counts bytes reaching the recording file and surfaces a write failure. The record controllers weren't touched at all.

R19 survives, stronger

Upstream made codec and executorService volatile but not prepared — and its new budget-exhausted branch writes prepared from the callback thread. That's R19's argument, not a replacement for it.

One line did go

AudioEncoder's shouldReset = resetTs. Upstream moved that assignment up to BaseEncoder. It was never a GPX change — the tell is that VideoEncoder's identical line merged with no conflict.

What arrived

Upstream changes4 groups

›
  • Per-second send-queue statistics. A default onStreamingStats on BitrateChecker, backed by a monitor that classifies the queue's byte trend. BaseSender.start() became suspend.
  • Encoder crash-recovery budget. Three resets in 30 seconds, then stop instead of looping. Two fields became volatile.
  • Camera2 white-balance lock and tap-to-meter. New AE/AWB entry points; metering regions cleared before an auto mode is re-applied.
  • ktor 3.5.2.

None of it is reachable from gpxstream-app. onStreamingStats is a default method the app doesn't override; the new color-format logic runs only for YUV420Dynamical and the app encodes from a GL surface; the camera APIs are additive. The one line that changes every stream start is BaseSender.start() cancelling a previous send job — that's the bench item.

Worth remembering

Gotchas3

›

The marker-count diff is the check that matters

Six conflicts were visible and got attention. The real risk is a silently auto-merged hunk eating a GPX line. Diffing git grep -o "GPX R.." | sort | uniq -c before and after catches it in one command. Run it every sync.

Same file ≠ same patch

Camera2ApiManager got +110 upstream lines and read alarming; all of it was in the AE/AWB request builders. Intersecting file lists gives you the shortlist, not the answer.

A stale doc baseline, fixed

The marker-coverage claim was measured against the original branch point. Once R26 merged upstream commits in, that diff also lists files upstream changed — it reported 78 files, not 32. Rebased on the merged upstream head.

App build failed on someone else's edit

A parallel session was live in the app's s3-camera-input worktree and fixed a CameraCore.kt error mid-run. If an app build fails in a module with no RootEncoder dependency, check git status before blaming the merge.
