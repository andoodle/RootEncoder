The hard part

What shaped the work3

›

The API break

BaseEncoder.type went from a MIME String to a Codec enum; getType()/setType() deleted. Every GPX patch that set a codec was written against the string. This is exactly why the two fork lines cannot be swapped.

It simplified the biggest item

The old record-codec patches existed largely to keep a MIME-string mutation exception-safe. An enum assignment cannot half-apply, so that wrapper is gone. The remaining try/catch guards MediaCodec.start() on a second hardware encoder.

Commit titles lied about scope

Three WHIP changes named in old commit titles are absent from that branch's final tree — auth reached upstream independently, and transport-cc/MID extensions plus H264 profile-level-id were removed by later commits. Derive scope from the diff, never the log.

A structural check that found a real gap

Comparing the file set changed by each branch caught GenericStream.kt, which had been analysed and then never applied. Worth re-running after any future re-apply.

Evidence

Bugs the patches prevent5

›
  • Permanent pipeline wedge — startRecord's catch cleared isRecording without stopping the sources, so a later startStream called startSources() twice and hit IllegalStateException: start() is valid only at Configured state; currently at Running state. Fixed by a dedicated sourcesRunning flag (cd89bb86b).
  • Process death mid-stream — RtmpSender.setVideoInfo threw on a null pps/vps while running on the MediaCodec callback thread, where no app-side catch can intervene (dabdccb17).
  • Dropped GL teardown — GlStreamInterface.stop() queued the release then called shutdownNow(), racing to cancel it (12f5afaaf).
  • Null dereference in encoder selection — getEncoderCapabilities() returns null on vendor codecs that advertise the mime (62d7009e8).
  • Silent recording loss — the MPEG-TS writer swallowed every write exception, so a full or wedged disk recorded nothing with no report (6794feb0a).
